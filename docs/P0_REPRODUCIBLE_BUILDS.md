# P0 — Reproducible dependency graph and build controls

The npm and Cargo lockfiles were generated by GitHub Actions on a temporary
trusted development branch. The bootstrap workflow was deleted after generation,
and is not part of the permanent CI.

## Locked builds

- Windows CI uses Node.js 24, `npm ci --no-audit --no-fund`.
- Electron runtime binary download is skipped in CI when doing the TypeScript/
  renderer build only. This does not validate the packaged executable.
- Rust CI on Windows and Linux uses `cargo clippy --locked` and
  `cargo test --locked` and separately enforces `cargo fmt`.
- Third-party metadata is archived as a CycloneDX dependency inventory.
- Dependencies may still need vulnerability updates; lockfiles do not
  establish correctness or absence of vulnerabilities.

## Release blockers

1. Manual verification of installed Electron Windows binary and preload.
2. Windows 11 actual DPI changes across multiple monitors.
3. Security review of all transitive dependency licenses, native binaries,
   fonts/icons, Electron/Chromium notices and installer.
4. Package signature and provenance strategy.
5. No physical disk I/O or formatting until later dedicated acceptance gates.

## Local checks

```powershell
npm ci
npm run build
npm run test:main
cargo fmt --all -- --check
cargo clippy --locked --workspace --all-targets -- -D warnings
cargo test --locked --workspace --all-targets
```

The UI build is not a disk formatter and cannot open physical disks.
